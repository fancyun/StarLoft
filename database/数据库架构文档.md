# StarLoft 星楼云 · 数据库架构文档

> 统一维护本仓库的数据库设计说明，建表定义以 `database/init.sql` 为准。

## 1. 概述

平台采用 **同一 MySQL 实例下的多库（分库）架构**，按业务域拆分数据库，业务之间相互隔离、互不干扰，便于权限收口与后续演进。

当前共规划 4 个库：

| 数据库 | 归属 | 状态 | 说明 |
| --- | --- | --- | --- |
| `starloft_sys` | 平台系统库 | 已启用 | 用户、管理员、实名记录、余额流水、充值订单、登录日志 |
| `starloft_kyc` | 实名认证产品库 | 已启用 | 认证订单、资源包、用户资源包 |
| `starloft_cs` | 云服务器产品库 | 预留 | 暂未建表 |
| `starloft_sms` | 短信服务产品库 | 预留 | 暂未建表 |

字符集统一为 `utf8mb4 / utf8mb4_general_ci`，存储引擎为 `InnoDB`。

## 2. 分库设计说明

- **`starloft_sys`（系统库）**：承载平台公共能力，即账号体系、余额与支付、登录审计日志。连接配置中的默认库即此库。
- **`starloft_kyc`（实名认证产品库）**：承载实名认证这一核心产品的业务数据（认证订单、资源包）。
- **`starloft_cs` / `starloft_sms`**：为后续云服务器、短信服务产品预留的独立库，遵循"一产品一库"的隔离原则。

> 约定：账户实名认证（source=1）不走认证订单表，其结果与详情单独存储于 `starloft_sys.kyc_personal`（个人实名）；企业实名存储于 `starloft_sys.kyc_enterprise`；API 调用（source=2）走 `starloft_kyc.auth_order`。

## 4. 关键设计点

- **单一业务流水号**：认证订单与实名记录统一使用平台随机生成的 `biz_no`（20 位，全平台唯一）作为唯一标识，废除商户/平台双流水号。
- **账户实名与 API 实名解耦**：`source=1` 账户实名仅写 `starloft_sys.kyc_personal`，不产生订单与计费；`source=2` API 调用走 `starloft_kyc.auth_order` 完整订单 + 计费流程。
- **企业实名独立**：企业实名记录单独存于 `starloft_kyc` 之外的 `starloft_sys.kyc_enterprise`（自助=法人扫脸 / 后台人工=公户验证），认证通过后落地 `user.is_kyc_verified=2`。
- **服务开通机制**：用户对某服务需先「开通」（`user_service`），开通时校验实名资格（如 kyc 服务要求企业实名），后续调用由服务中间件校验是否已开通，避免每次调用重复校验实名。
- **配置统一走环境变量**：第三方业务配置（FinAuth、腾讯云短信/验证码/SES、支付宝、微信、KYC 单价）全部由 `.env` 环境变量管理，后端启动时加载，修改后重启生效。数据库连接、Redis、JWT 等基础设施同样由 `.env` 管理。
- **余额与资源包双计费**：认证消耗支持余额（balance_log）或资源包次数（user_resource_pack）两种方式。

## 5. 初始化与表结构同步

- **初始化脚本**：`database/init.sql` 先 `DROP DATABASE` 彻底重建 4 个库与全部表，再写入默认管理员与资源包种子数据。**该脚本会永久删除旧库数据，仅限无存量数据时执行。**
- **结构同步**：后端启动时 GORM `AutoMigrate` 会自动同步表结构（只增不减，不清理旧字段），与 init.sql 不冲突。
- **Docker 本地部署**：`docker-compose.yml` 中 MySQL 容器首次启动时将 `database/init.sql` 复制到 `/docker-entrypoint-initdb.d` 自动执行，完成本地建库与初始化。

## 6. 连接配置

后端通过环境变量（由 `.env` 提供）连接数据库。分库库名 **`starloft_sys` / `starloft_kyc` 已固定写死为代码常量**（见 `internal/model/database.go`，需与 `database/init.sql` 建库名一致），不再通过环境变量配置；实际连接默认连 `starloft_sys`，并通过全限定表名跨库访问 `starloft_kyc`。`.env` / `docker-compose.yml` 仅配置数据库连接主机的 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD` 等连接参数。
